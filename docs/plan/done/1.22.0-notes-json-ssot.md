# Plan — per-project tasks & notes move into the repo (`.akidevsync/notes.json`)

**Status**: ✅ DONE — WP-1…WP-6 all landed, runtime verified on Mac. One deliberate deviation from §5: `migrateLegacyProjectNotes` writes through `applyTaskEdit` (not `write_project_notes` directly), so acceptance criterion 1 (one call site) holds for the migration too.

**Ships in**: 1.22.0 (`package.json` + `Cargo.toml` bumped from 1.21.0)
**Supersedes for the data layer**: `docs/plan/done/1.20.0-terminal-and-remote-sync.md` §2 (PERSIST-1) — invariant unchanged, only backing file moves
**Feature doc**: `docs/feat/project-task-list.md` § "Data and persistence"

Two blockers found in adversarial review, both fixed before DONE was written:
1. **Late read overwriting a fresh edit** — a `read_project_notes` `spawn_blocking` call started on modal-open could resolve *after* a write and reseed the store with stale content. Fix: a per-id generation counter in `projectNotesStore.js`; every mutation bumps it, every read discards its result if no longer current.
2. **Writable stale entry surviving a `local_path` change** — `applyProjectConfig` calls `refreshProjectNotes`, but the window until that read lands leaves the old directory's `ok` entry in place. Fix: set entry to `'unknown'` (non-writable) **synchronously** first, then refresh.

Two smaller fixes: failed *refresh* was blanking on-screen text (violating §4 property 2); two rapid edits produced a false `clobbered` toast against the app's own previous write — fixed by serialising writes per project id (`queueNotesWrite`).

---

## 1. Context and decision

> **The local repo directory is the single source of truth. Remote hosts only run code; they are never authoritative.**

Per-project `tasks[]` and `notes` move out of `projects.json` (app-scoped, non-portable) into:

```
<project.local_path>/.akidevsync/notes.json
```

The file is meant to be **committed to the repo** — that is the point of the move. `projects.json` keeps only rsync config.

Two consequences:
- The file carries an `about` key linking to this app's public repo.
- Default rsync excludes must prevent a `--delete` PULL from deleting this file (§7) — this lands *before* any data moves there.

The directory owns the data. Two project rows pointing at the same `local_path` share one `notes.json` and one task list — correct under the decision above.

## 2. File schema

Path: `<local_path>/.akidevsync/notes.json`. One file per project directory. Pretty-printed (meant to be diffed in git).

```json
{
  "about": "https://github.com/lacvietanh/aki-dev-sync",
  "schema": 1,
  "notes": "Staging URL, deploy notes, credentials…",
  "tasks": [
    {
      "id": "task-1753600000000",
      "title": "Wire up the notes file",
      "detail": "",
      "done": false,
      "pin": false,
      "wish": false,
      "created_at": 1753600000000,
      "updated_at": 1753600000000
    }
  ],
  "updated_at": 1753600000123
}
```

| Field | Type | Owner | Notes |
| :-- | :-- | :-- | :-- |
| `about` | `String` | Rust const | App's public repo URL. Rewritten on every write — self-heals if hand-deleted. |
| `schema` | `u32` | Rust const | Currently `1`. Reserved for future shape change; nothing branches on it in 1.22.0. |
| `notes` | `String` | JS | Free text, `.trim()`-ed by the UI. |
| `tasks` | `Vec<serde_json::Value>` | JS | **Opaque to Rust** — same as `global_note.rs`. Shape and migrations owned by `normalizeTasks`. |
| `updated_at` | `u64` (ms epoch) | Rust | Staleness fence for §3. Rust stamps it because only Rust knows when bytes landed. |

Rust struct (`src-tauri/src/project_notes.rs`):

```rust
#[derive(serde::Serialize, serde::Deserialize, Clone, Default)]
pub struct ProjectNotesFile {
    #[serde(default)] pub about: String,
    #[serde(default)] pub schema: u32,
    #[serde(default)] pub notes: String,
    #[serde(default)] pub tasks: Vec<serde_json::Value>,
    #[serde(default)] pub updated_at: u64,
}
```

`#[serde(default)]` on every field — a file written by a future version or hand-trimmed to `{"notes":"x"}` still loads without migration.

### Read result is a tagged Result, not an Option

A missing file and an unreadable file are different facts and must not collapse into "empty":

```rust
pub enum ProjectNotesStatus { Ok, Missing, Unavailable, Corrupt }

pub struct ProjectNotesRead {
    pub status: ProjectNotesStatus,
    pub file: Option<ProjectNotesFile>,   // Some only when status == Ok
    pub error: Option<String>,
}
```

- `Ok` — file read and parsed.
- `Missing` — dir is readable, `.akidevsync/notes.json` not there. Normal for new projects. **Writable.**
- `Unavailable` — `local_path` is not a directory (unmounted volume, deleted folder, permission denied). **Not writable.**
- `Corrupt` — file exists but is not valid JSON (git merge-conflict marker is the realistic case). **Not writable.** Deliberately not `unwrap_or_default()` — defaulting would mean "show empty, then save empty over conflicted notes".

## 3. Module boundaries

### New: `src-tauri/src/project_notes.rs`

Owns the file: its path, shape, atomic write, and lock. Nothing else in Rust touches `.akidevsync/`.

| Command | Signature | Responsibility |
| :-- | :-- | :-- |
| `read_project_notes` | `async fn(local_path: String) -> Result<ProjectNotesRead, String>` | One project. Never `Err` for missing/corrupt — those are statuses. |
| `read_project_notes_map` | `async fn(targets: Vec<ProjectNotesTarget>) -> Result<HashMap<String, ProjectNotesRead>, String>` | Batch read at boot. One failing target never fails the batch. |
| `write_project_notes` | `async fn(local_path, notes, tasks, base_updated_at) -> Result<ProjectNotesWrite, String>` | Read-modify-write. `None` field = "leave on disk alone". Returns `{ file, clobbered }`. |

All `spawn_blocking` — `local_path` is the same path class `projects.rs` documents as able to stall for tens of seconds on an unhealthy mount.

Internals:
- `fn notes_path(local_path: &str) -> PathBuf` — the ONE place `.akidevsync/notes.json` is spelled.
- `validate_path_segment` reused before touching the path.
- Write via `crate::system::write_atomic` (temp + rename).
- `static WRITE_LOCK: tokio::sync::Mutex<()>` — one global mutex, not per-path. Writes are small, rare, and user-paced.
- **Concurrent-writer answer:** fresh read inside the lock — a `git pull` changing `notes` while user edits `tasks` survives. For same-field: last-write-wins but never silent (`clobbered: true` + Toast + re-hydrate). Git is the recovery mechanism.

## 4. Failure / edge matrix

Rule: **never show empty and then write empty.** A read that did not succeed → read-only UI → visible before the user types.

| Condition | `status` | UI | Write |
| :-- | :-- | :-- | :-- |
| File present and valid | `ok` | normal | allowed |
| Dir readable, no `.akidevsync/` | `missing` | normal, empty | allowed — write creates dir + file |
| `local_path` not a directory | `unavailable` | badges blank; title `— unavailable`; inputs disabled | **refused** |
| Dir readable, file unreadable | `unavailable` | same | refused |
| File present, invalid JSON | `corrupt` | title `— corrupt`; tooltip = parse error | refused |
| Volume unmounts mid-modal | still `ok` | unchanged | write fails → Toast; store left as-is |
| `local_path` edited | re-read | shows new directory | per new status |
| Two rows, same `local_path` | both `ok` | both show it | both allowed, serialized by lock |
| Git pull changed file | `ok` (stale) | refreshed on modal open | write lands, `clobbered: true` → Toast |
| Companion (phone) | host read | mirrored | via host-side action |

Two properties guaranteed:
1. **A refused write never mutates the store** — guard in `applyTaskEdit` before the store assignment.
2. **A failed write never clears the UI** — on-screen text is the user's only remaining copy at that moment.

## 6. Migration

**Trigger:** every `loadData`, after `hydrateProjectNotes`. **Never writes a flag** — absent key IS the marker.

| Legacy fields | Disk status | Action |
| :-- | :-- | :-- |
| empty/absent | any | no-op |
| non-empty | `missing` | write to disk; delete legacy fields; mark list dirty |
| non-empty | `ok` | file wins (SSOT). Delete legacy fields only if file content is non-empty; else treat as `missing` |
| non-empty | `unavailable`/`corrupt` | skip entirely; retry next launch |

One-way: nothing ever writes `tasks`/`notes` back into `projects.json`. `skip_serializing_if = "Option::is_none"` enforces it at Rust level.

Legacy field removal: 1.23.0 (one release cycle, same as `sync_git` precedent).

## 7. Default excludes redesign

### Why `.akidevsync/` is excluded from both directions

1. **PULL is the load-bearing half.** `delete_on_pull` defaults true; `--delete` on a remote that lacks the directory **deletes the user's task list**. Excluding from pull is not a preference — it is the guard that makes the location safe.
2. **The host has no use for it** — the host runs code; it does not read the task list.
3. **It leaks.** The notes field's placeholder is *"general project notes, credentials, or context"* — pushing copies credentials onto a shared server.
4. **A remote copy can flow back over the SSOT** on a later `--delete`-less PULL.
5. **Consistency with `.claude/`** — already excluded in both directions by default.
6. **Side benefit:** keeps notes edits out of the sync baseline — editing a note does not create a phantom "pending push".

### Concrete defaults

```js
pull_excludes: [".DS_Store", "*.log", ".git/", ".akidevsync/", "node_modules/", ".nuxt/", ".output/", ".wrangler/", "dist/", ".claude/"],
push_excludes: [".DS_Store", "*.log", ".akidevsync/", "node_modules/", ".nuxt/", ".output/", ".wrangler/", "dist/", ".claude/"],
```

### Existing projects

`migrateNotesExcludes(projectList)` — reuses `ensureEntry`, adds `.akidevsync/` to both lists if absent, touches no other entry. Not doing new-projects-only: the pull case destroys data for any user who never visits the exclude editor.

**Not doing:** touching `.gitignore` — the file is meant to be committed.

## 8. Non-goals (1.22.0)

- No merge/conflict resolution — last-write-wins + `clobbered` Toast. Git is the recovery path.
- No file watcher — refresh on load, modal open, and `local_path` change.
- No git integration — app never `git add`s or commits.
- No per-task files, Markdown format, or directory of notes — one JSON file, one shape.
- No `schema` branching — field written and read; no version-dispatch until a second shape exists.
- No companion filesystem access — no new entry in `COMPANION_ALLOWED_COMMANDS`.
- Global Note does not move — not project-scoped, stays in app data.
- No repair gesture for `corrupt` file — read-only + parse error is the full answer.
- No `.akidevsync/` beyond `notes.json`.

## 9. Acceptance criteria

1. **One writer.** `grep -rn "write_project_notes" src/` → exactly one call site: `applyTaskEdit` in `remoteActions.js`.
2. **One path spelling.** `grep -rn "akidevsync" src-tauri/src/` → only inside `project_notes.rs::notes_path`. In `src/` → only the two exclude defaults and `migrateNotesExcludes`.
3. **`projects.json` no longer carries the data** after one app launch.
4. **`about` and `schema` always present** — deleting both keys and making any edit restores them.
5. **Unmounted volume:** no task badges (not `0`); modal title `— unavailable`; notes `readonly`; add-row disabled; `applyTaskEdit` returns without mutating the store.
6. **Corrupt file:** `<<<<<<< HEAD` yields `corrupt`, same read-only UI, parse error in tooltip, file bytes unchanged.
7. **No silent empty-overwrite:** no code path calls `write_project_notes` with `notes: ''` / `tasks: []` unless the user actually emptied them.
8. **Every serde field has `#[serde(default)]`** — `{"notes":"x"}` loads as `ok` without dropping `tasks`.
9. **Field-scoped writes:** notes-only edit leaves `tasks` byte-identical on disk, and vice versa.
10. **Multi-entity guard:** edit, removal, and `local_path` change on project A leave project B's `notes.json` and store entry untouched.
11. **Companion:** `COMPANION_ALLOWED_COMMANDS` unchanged. Phone can read/edit tasks/notes; edits land in the correct `notes.json` on the Mac.
12. **Excludes:** every existing project has `.akidevsync/` in both lists after one launch; new projects created with both entries.
13. **`spawn_blocking`:** all three commands are `async fn` with bodies inside `spawn_blocking`.
14. **Docs:** `docs/feat/project-task-list.md` § "Data and persistence" describes `notes.json`; `docs/index.md` lists this plan; `README.md` and `IntroModal.vue` mention project notes live in the repo.
