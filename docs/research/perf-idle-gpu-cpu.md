### Ranked shortlist — highest-cost idle offenders

1. **`.badge-dot` `pulse-red 2s infinite` (`AppHeader.vue:1121`, always mounted).** CONFIRMED, top suspect: a permanently-mounted, unconditional CSS animation combining `transform: scale()` + `box-shadow` on a fixed top-chrome element — both are compositor/paint properties, running for the entire app session regardless of any panel state. Cheapest sufficient fix: gate `.badge-dot`'s presence behind whatever "unseen intro" condition it signals (a `v-if` instead of always-rendering the dot), or drop `infinite` for a fixed small repeat count if the badge is meant to catch attention once, not forever. Risk: low — purely presentational, no state dependency found in this pass beyond the button it sits in.
2. **`.skeleton-box` (`main.css:420`) if a caller ever leaves it mounted past a failed load.** CONDITIONAL but highest blast radius if the ASSUMPTION above is wrong, because it is a shared class used app-wide (plan's own words: "Highest-suspicion candidate"). Not confirmed or ruled out here — the class itself is inert without a stuck caller. Cheapest sufficient fix, if a stuck case is later found: a load-timeout fallback that swaps the skeleton for an error state instead of leaving it mounted indefinitely. Risk: needs the runtime check below before any fix is justified — fixing an unconfirmed leak risks masking a real stalled-fetch bug instead of surfacing it.
3. **`UsageCircle.vue` + `AgentUsage.vue`'s `agoTimer`, two always-running 10s JS timers while the usage panel is mounted (which is unconditional per `App.vue`).** CONFIRMED running, but JS-only (no CSS/compositor work) — much lower GPU relevance than the two CSS animations above, more a CPU/wake-count concern. Cheapest sufficient fix, if profiling shows this matters: no code change needed for `agoTimer` (already refcounted/shared by design); `UsageCircle`'s per-card 10s timer could adopt the same module-scope refcount pattern `agoTimer` already uses, since multiple `UsageCircle` instances currently each run their own independent 10s interval. Risk: low, same pattern already proven safe in the same file.

Everything else in the plan's candidate list (skeleton block in `AgentUsage.vue`, `.status-dot`, `ResizeObserver`/rAF, `bridge.js` ping loop, `ccClockTimer`, all 14 `transition: all`) is CONDITIONAL or RULED OUT per the table above and is not a standing idle cost under normal operation.

### What is NOT statically decidable
Static reading proves *whether* a candidate runs while idle in the general case, but not *how much* GPU/CPU it actually costs on the real compositor, nor whether some other code path outside this candidate list (browser devtools overhead, WebKit's own repaint heuristics, a GPU-accelerated `backdrop-filter`/`box-shadow` elsewhere not flagged by the plan's grep patterns) is the true dominant cost. This matches `coding.B3`: the real-cost ranking needs a profiler run on the actual Mac target, not more code reading.
